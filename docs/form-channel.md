# Канал приёма ответов (S0.2)

Решение по способу доставки ответов из формы в дашборд. Проверено по официальной
документации Яндекса и по доступности сервисов, а не по памяти.

---

## Что выяснилось

Из [документации Яндекс Форм про HTTP-запросы](https://yandex.ru/support/forms/ru/send-request):

1. **Интеграция работает только по IPv6.** Формы не отправляют HTTP-запросы на IPv4-адреса,
   пакеты приходят из сети `2a02:6b8:c00::/40`. Если у приёмника нет публичного IPv6 —
   запрос просто не дойдёт, и это выяснится на сцене, а не сегодня.
2. **Таймаут 5 секунд**, при ошибке — до 7 повторов в течение 30 минут. Повторяются:
   таймаут, сетевая ошибка, 5XX, 404.
3. **Дубликаты возможны штатно**: форма может отправить один и тот же ответ дважды.
   Для склейки есть заголовок `x-delivery-id`.
4. Успех — код 200, 201 или 202. Для JSON-RPC успех определяется отсутствием `error`
   в теле ответа.
5. Формы умеют не только JSON-RPC, но и произвольный HTTP-метод с телом и заголовками —
   этого достаточно, чтобы отправить обычный JSON.

Google Forms проверен как альтернатива: форма → связанный Google Sheets → опубликованный
CSV. Работает по IPv4, входящий трафик не нужен, но зависит от доступности Google
на площадке, а в РФ она нестабильна.

---

## Решение

| Роль | Канал | Почему |
|---|---|---|
| Основной | **Яндекс Формы → HTTP-запрос JSON → `/api/ingest`** | Заказчик — МГТС, Яндекс Формы уместнее и стабильнее; нужен только публичный IPv6 |
| Резерв на площадке | **Своя страница `/form`** | Ноль внешних зависимостей: отправляет JSON прямо в приёмник. Если сеть подведёт — сценарий всё равно живой |
| Резерв для истории | **Импорт XLSX/CSV** | По письму организаторов данные у МГТС уже в Excel, массовая загрузка нужна в любом случае |
| Экзотика | Google Sheets → CSV-поллинг, IMAP | Оставлены в коде как адаптеры, на сцене не используются |

**IPv6 закрывается одним из двух способов**, выбираем на месте:

- деплой контейнера на VPS с публичным IPv6 — тогда форма бьёт прямо в него;
- `cloudflared tunnel` на ноутбуке: публичное имя Cloudflare отдаётся по IPv6, а до
  приёмника трафик идёт исходящим соединением, входящий IPv6 на ноутбуке не нужен.

Для прямого VPS процесс должен слушать `--host ::`, иначе IPv6-пакеты не примутся.

## Что из этого уже зашито в код

Приёмник написан под эти ограничения, а не под «идеальный» вебхук:

- **Отвечает сразу.** Разбор, LLM и пересчёт идут после ответа, иначе 5 секунд не уложить.
- **Всегда 200.** Даже если тело не разобралось: 404 и 5XX заставляют форму повторять
  запрос семь раз. Ошибка пишется в лог, ответ всё равно успешный.
- **Дедупликация по `x-delivery-id`**, плюс хэш содержимого — на случай, если заголовка нет.
- **Сырой payload сохраняется целиком** в `ingest_log`: на финале видно, что именно прислала
  форма, без догадок и без перезапуска.
- **JSON-RPC-совместимый ответ**, если вход выглядит как JSON-RPC.

## Как проверяем до финала

1. `make up`, открыть `http://localhost:8000/api/health`.
2. Открыть `/form`, отправить тестовый ответ, увидеть его в логе на главной.
3. Создать Яндекс Форму по [forms.md](forms.md), в интеграциях — HTTP-запрос на адрес
   приёмника (через VPS или туннель), отправить ответ, увидеть его в логе.
4. Проверить дважды: тот же ответ не должен появиться дважды.
5. Записать фактическое время от отправки до появления в логе.

Пункты 3–5 требуют аккаунта Яндекса и публичного адреса — это единственная часть фазы 0,
которую нельзя сделать без тебя. Всё остальное готово и проверено локально.
