Короткий путь: мок-данные уже лежат в репозитории, заливаются одной командой.
Форма нужна для живого сценария на защите — но проверить её можно на этих же данных.

## 2. Создать форму

Делаем форму стажёра. Названия кнопок в Яндексе могут отличаться на пару слов, но порядок такой.

1. Открой `forms.yandex.ru` → **Создать форму**.
2. Вверху впиши название: `Пульс · анкета стажёра`.
3. **Добавить вопрос** → тип **Короткий текст** → заголовок `Фамилия и имя` → включи **Обязательный**.
4. Ещё один короткий текст → `Наставник` → обязательный.
5. Короткий текст → `Направление` → необязательный.
6. **Один ответ** → заголовок `Месяц стажировки` → варианты, по одному в строке:
   ```
   M1
   M2
   M3
   M4
   M5
   M6
   ```
   Обязательный. Другие значения приёмник не разберёт.
7. Шесть вопросов типа **Линейная шкала** (в некоторых версиях — «Шкала»):
   минимум `1`, максимум `10`, шаг `1`, подписи краёв «совсем нет» и «полностью».
   Заголовки:
   - `Насколько тебе сейчас интересно то, чем ты занимаешься?`
   - `Насколько понятно, какие у тебя задачи и чего от тебя ждут?`
   - `Насколько тебе хватает поддержки и обратной связи от наставника?`
   - `Насколько нагрузка сейчас комфортна?`
   - `Насколько ты чувствуешь себя частью команды?`
   - `Насколько ты уверен, что хочешь и сможешь остаться в компании после стажировки?`
8. Два **Длинных текста**:
   - `Что за последний месяц изменилось к лучшему?`
   - `Что мешает работать или снижает желание продолжать?`
9. **Опубликовать**.

Вторая форма — копия с «наставническими» формулировками из `docs/forms.md`.
В интеграции у неё будет только одна разница: `s_role` = `mentor`.

## 3. Подключить интеграцию

1. В форме открой вкладку **Интеграции**.
2. **Добавить группу действий** → внутри группы нажми **API** → **Запрос JSON-RPC POST**.
3. Заполни:

| Поле | Значение |
|---|---|
| URL | `http://[2a02:408:7722:54:77:222:47:41]:8000/api/ingest` |
| Метод | `submit` |

4. Добавь параметры. У каждого значения справа есть кнопка вставки переменной:
   выбери **Ответ на вопрос** и нужный вопрос.

| Имя параметра | Значение |
|---|---|
| `s_name` | вопрос «Фамилия и имя» |
| `s_mentor` | вопрос «Наставник» |
| `s_direction` | вопрос «Направление» (включи «Передавать, если значение задано») |
| `s_month` | вопрос «Месяц стажировки» |
| `s_role` | впиши руками `intern` (во второй форме — `mentor`) |
| `f_motivation` | вопрос про интерес |
| `f_clarity` | вопрос про понятность задач |
| `f_mentor` | вопрос про поддержку наставника |
| `f_workload` | вопрос про нагрузку |
| `f_inclusion` | вопрос про команду |
| `f_future` | вопрос про будущее в компании |
| `q_better` | вопрос «Что изменилось к лучшему» |
| `q_barrier` | вопрос «Что мешает» |

5. Для `q_better` и `q_barrier` нажми на вставленную переменную и выбери фильтр **JSON**.
   Без него перевод строки или кавычка ломают тело запроса.
6. Сохрани.

Если параметр в интерфейсе не добавить, приёмник просто не увидит поле: анкета
создастся, но без этого фактора. Проверяется журналом.

## 4. Проверить одним ответом

Открой `fixtures/form-kit/manual-test.md` — там готовые значения для Петрова Алексея
за M6. Заполни форму и отправь.

Что должно быть:

1. На дашборде, внизу справа, кнопка **журнал приёма** → новая строка `accepted`,
   внутри `submission: created`, `analysis: queued`.
2. Через пару секунд в списке появляется **Петров Алексей**, индекс около 84,
   сигналы «намерение уйти» и «выгорание», в карточке — цитаты из текста.

Если строка есть, а человека нет — смотри месяц: он должен быть выбран `M6`.

## 5. Залить весь набор

Когда форма проверена, остальные 59 ответов можно не набирать руками:

```bash
.venv/bin/python scripts/replay_form_kit.py \
  --url http://77.222.47.41:8000/api/ingest
```

Скрипт отправляет те же JSON-RPC, что и форма, по одной анкете за запрос.
Ожидаемый вывод:

```
отправлено 60: accepted=60, создано=60, обновлено=0, дубликатов=0, без пары=0, отклонено=0
```

Повторный запуск ничего не испортит: те же ответы дадут `дубликатов=60`.

Только один месяц (например, для показа без истории):

```bash
.venv/bin/python scripts/replay_form_kit.py --month M6
```

## 7. Убрать мок-данные

Перед загрузкой настоящих людей:

```bash
make clean-kit
```

или на сервере:

```bash
ssh root@77.222.47.41 'cd /opt/pulse && docker compose exec -T pulse \
  python -m tools.clean_form_kit'
```

Удаляются только пары из набора и их записи в журнале; остальные данные не трогаются.
Полный сброс базы — `docker compose exec pulse python -m tools.seed_demo --reset`
(перезальёт демо) или удаление `data/app.db`.

## 8. Если не работает

| Симптом | Причина |
|---|---|
| В журнале пусто | запрос не дошёл: IPv6, ufw, адрес без квадратных скобок |
| `status: rejected` | включён `INGEST_KEY`, а параметр `key` не передан |
| `unparsed` | у длинных текстов не стоит фильтр JSON |
| `unmatched` | месяц не из `M1`…`M6` или пустое имя |
| Анкета есть, разрыва нет | у пары не сдана вторая анкета — это нормально |
| Человек «дублируется» | в форме имя набрано иначе: регистр и пробелы мы склеиваем, но не опечатки |

Подробная диагностика по самой форме — в [yandex-forms.md](yandex-forms.md).
