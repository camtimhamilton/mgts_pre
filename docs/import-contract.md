# Контракт импорта (фаза 1) — заморожен

Эндпоинты живут только в `app/routers/imports.py`. Фронт страницы импорта строится
по этому документу и не зависит от внутренностей парсера.

Общий принцип: **разбор всегда приводит файл к длинному виду** (строка = одна анкета:
пара, роль, месяц, шесть оценок, два текста). Широкий формат и книга с двумя листами
схлопываются в него на этапе preview, поэтому у commit один код-путь.

---

## POST /api/import/preview

`multipart/form-data`:

| Поле | Обяз. | Смысл |
|---|---|---|
| `file` | да | `.xlsx`, `.xlsm` или `.csv` |
| `sheet` | нет | имя листа; по умолчанию первый непустой |
| `default_role` | нет | `intern` или `mentor`, если роли в файле нет |

Ответ `200`:

```json
{
  "file": { "name": "surveys.xlsx", "size": 20480, "sheets": ["Стажёры", "Наставники"] },
  "format": "long",
  "confidence": 0.86,
  "columns": ["ФИО", "Наставник", "Направление", "Месяц", "Мотивация", "Ясность", "…"],
  "rows_total": 60,
  "sample": [{ "ФИО": "Иванов Пётр", "Месяц": "M1", "Мотивация": "7" }],
  "mapping": {
    "intern_name": "ФИО",
    "mentor_name": "Наставник",
    "direction": "Направление",
    "month": "Месяц",
    "role": null,
    "default_role": "intern",
    "factors": {
      "motivation": "Мотивация",
      "clarity": "Ясность",
      "mentor": null,
      "workload": null,
      "inclusion": null,
      "future": null
    },
    "open": { "q_better": null, "q_barrier": "Комментарий" }
  },
  "warnings": ["оценки по трём факторам не найдены — они будут помечены как отсутствующие"]
}
```

`format`: `long` | `wide` | `two_sheet` | `unknown`.
`confidence` — насколько уверенно распознан формат, 0…1.
`mapping` — предложение, которое пользователь может переопределить в UI.

Для `wide` и `two_sheet` в `columns` приходят **уже схлопнутые** имена колонок
(`"Ясность M3"`), и `rows_total` считается после схлопывания. Поле `mapping` всегда
описывает длинный вид.

Ошибки: `415` — расширение не поддержано, `422` — файл не читается или пуст.
Файл в базу не пишется, preview безопасен и повторяем.

## POST /api/import/commit

`multipart/form-data`:

| Поле | Обяз. | Смысл |
|---|---|---|
| `file` | да | тот же файл, что в preview |
| `mapping` | да | JSON-строка с объектом из preview (можно изменённым) |
| `sheet` | нет | как в preview |
| `default_role` | нет | как в preview |
| `source` | нет | метка источника, по умолчанию `import` |

Ответ `200`:

```json
{
  "created": 57,
  "updated": 0,
  "duplicates": 3,
  "errors_total": 1,
  "unmatched": 1,
  "errors": [{ "row": 42, "error": "не удалось определить месяц" }]
}
```

Правила:

- идемпотентность: ключ `(пара, роль, месяц)`; тот же текст — `duplicates`, другой — `updated`;
- строки без имени стажёра не роняют импорт: они уходят в `ingest_log` со статусом
  `unmatched` и считаются в `unmatched`;
- ошибки по строкам не прерывают файл, в ответе первые 20 и общее число;
- `source` попадает в `submissions.source`.

## Форматы, которые обязаны загружаться

Тестовый «зоопарк» лежит в `fixtures/zoo/`, каждый файл — отдельный случай:

1. `long_ru.csv` — канонический длинный, русские заголовки, UTF-8 BOM.
2. `long_cp1251.csv` — то же в cp1251, оценки с запятой (`7,5`).
3. `wide_months.xlsx` — широкий: колонки `Ясность M1`, `Ясность M2`, …; схлопывается.
4. `two_sheets_roles.xlsx` — лист «Стажёры» и лист «Наставники», роль из имени листа.
5. `messy_headers.csv` — другой порядок, лишние колонки, пробелы, роль отдельной колонкой.

Приёмка: все пять грузятся без правки кода, повторная загрузка даёт `duplicates`,
а не новые строки.
