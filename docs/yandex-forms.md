# Подключение Яндекс Форм

Пошаговая инструкция: форма → приёмник → дашборд. Проверять лучше в том порядке,
в каком написано — каждый шаг заканчивается наблюдаемым результатом.

---

## Что уже готово

| Что | Значение |
|---|---|
| Адрес приёмника | `http://[2a02:408:7722:54:77:222:47:41]:8000/api/ingest` |
| IPv6 | `2a02:408:7722:54:77:222:47:41`, порт 8000 открыт в ufw |
| Приёмник | отвечает 200 всегда, JSON-RPC понимает, дубликаты склеивает |
| Журнал | `http://77.222.47.41:8000/api/ingest/log` и кнопка «журнал приёма» в подвале дашборда |

Яндекс Формы умеют отправлять HTTP-запрос **только по IPv6** (диапазон источников
`2a02:6b8:c00::/40`), с таймаутом 5 секунд и до семи повторов при ошибке.
Поэтому адрес — IPv6-литерал в квадратных скобках, а приёмник отвечает сразу,
не дожидаясь модели.

---

## Шаг 0. Проверить сервер без формы

На любой машине с Python:

```bash
python3 scripts/simulate_yandex.py \
  --url 'http://[2a02:408:7722:54:77:222:47:41]:8000/api/ingest' \
  --name 'Тест Подключения'
```

Скрипт отправляет ровно такой JSON-RPC, какой пришлёт форма. Ожидаемый ответ:

```json
{
  "jsonrpc": "2.0",
  "result": {"ok": true, "id": 12, "duplicate": false, "status": "accepted",
             "submission": {"id": 143, "status": "created"}, "analysis": "queued"},
  "id": 1
}
```

Если здесь ошибка — форму настраивать рано: проверь `scripts/check_ipv6.sh` на сервере
и что порт 8000 открыт снаружи.

---

## Шаг 1. Создать форму

Вопросы — по [forms.md](forms.md). Типы важны: шкала должна отдавать число,
месяц — один из вариантов `M1`…`M6`, иначе приёмник не разберёт ответ.

| Вопрос | Тип в Яндекс Формах | Обязательный |
|---|---|---|
| Фамилия и имя | Короткий текст | да |
| Наставник | Короткий текст | да |
| Направление | Короткий текст | нет |
| Месяц стажировки | Один ответ: `M1`…`M6` | да |
| Шесть вопросов из forms.md | Линейная шкала 1–10 | да |
| Что изменилось к лучшему | Длинный текст | нет |
| Что мешает | Длинный текст | нет |

Сначала делаем форму стажёра — она приоритет. Форма наставника — копия с другими
формулировками, отличается только константой роли в интеграции.

---

## Шаг 2. Добавить интеграцию

В форме: **Интеграции → Добавить группу действий → API → Запрос JSON-RPC POST**.

| Поле | Значение |
|---|---|
| URL | `http://[2a02:408:7722:54:77:222:47:41]:8000/api/ingest` |
| Метод | `submit` |

Параметры (имя → значение). Значения — переменные «Ответ на вопрос»: в поле справа
есть кнопка вставки переменной.

| Имя параметра | Значение |
|---|---|
| `s_name` | ответ «Фамилия и имя» |
| `s_mentor` | ответ «Наставник» |
| `s_direction` | ответ «Направление» (включи «Передавать, если значение задано») |
| `s_month` | ответ «Месяц стажировки» |
| `s_role` | константа `intern` (для второй формы — `mentor`) |
| `f_motivation` … `f_future` | ответы на шесть шкал, по имени фактора |
| `q_better` | ответ «Что изменилось к лучшему» |
| `q_barrier` | ответ «Что мешает» |
| `key` | только если задан `INGEST_KEY` на сервере |

**Про длинный текст.** Перевод строки или кавычка ломают JSON, если вставить текст
как есть. Для `q_better` и `q_barrier` выбери у переменной фильтр **JSON**.
Если после проверки в журнале статус `unparsed` — замени фильтр на **Sanitize string**:
он вырезает спецсимволы, текст станет суше, но запрос точно пройдёт.

**Почему JSON-RPC, а не «запрос заданным методом».** В JSON-RPC параметры собирает
сама платформа: не нужно вручную писать тело и экранировать кавычки. Заголовки
JSON-RPC не поддерживает, поэтому ключ, если он включён, передаётся полем `key`.

---

## Шаг 3. Опубликовать и проверить

1. Опубликуй форму и заполни её как стажёр: имя, месяц, оценки, текст.
2. Открой на дашборде «журнал приёма» (внизу справа).
3. Ожидаемо: новая строка `accepted`, внутри — `submission: created`, `analysis: queued`.
4. Через пару секунд на дашборде всплывает «Новый ответ: M5, риск …» — это SSE.

Если в форме открыть **Интеграции → Выполненные интеграции**, там видно ошибки
доставки: таймаут, отказ соединения, ошибка в теле.

---

## Шаг 4. Вторая форма

Скопируй форму, поменяй формулировки вопросов на «наставнические» из
[forms.md](forms.md), в интеграции оставь всё как есть, кроме `s_role` → `mentor`.
Адрес, параметры и фильтры те же.

Если вторая форма не успевается — работает одна: разрыв скрывается, веса
перенормируются, в карточке плашка «нет анкеты наставника».

## Если не работает

| Симптом | Что проверить |
|---|---|
| В журнале пусто, в «Выполненных интеграциях» таймаут | IPv6 на сервере, ufw, порт 8000; URL с квадратными скобками |
| Статус `unparsed` | фильтр JSON у длинных текстов, лишние переносы в теле |
| Статус `rejected` | `INGEST_KEY` задан, а поле `key` пустое или неверное |
| `unmatched` | месяц не `M1`…`M6` или пустое имя |
| `duplicate: true` | нормально: Яндекс повторил запрос, второй раз не создаём |
| Запись есть, дашборд не обновился | открой журнал: если `analysis: queued`, но снапшота нет — смотри логи контейнера |

Диагностика на сервере:

```bash
ssh root@77.222.47.41 'cd /opt/pulse && docker compose logs --tail=50 pulse'
```

## Ограничения Яндекса, о которых стоит помнить

- **Только IPv6.** Если у сервера пропадёт IPv6, интеграция перестанет работать молча:
  запрос не дойдёт, а форма покажет ошибку в истории.
- **5 секунд.** Приёмник отвечает сразу; если когда-нибудь перед ним появится прокси,
  его таймаут должен быть меньше пяти секунд.
- **Повторы и дубли.** До семи попыток; склейка по `x-delivery-id`, плюс проверка
  содержимого — повтор не создаёт вторую анкету.
- **HTTP без TLS.** Если форма откажется отправлять на `http://`, нужен HTTPS-адрес:
  тогда либо домен с сертификатом, либо `cloudflared tunnel` (даёт https-имя с AAAA).

## Безопасность

По умолчанию приёмник открыт: кто угодно может отправить JSON. Для демо это терпимо,
но перед финалом стоит включить ключ:

```bash
ssh root@77.222.47.41 'cd /opt/pulse && sed -i "s/^INGEST_KEY=.*/INGEST_KEY=СЛУЧАЙНАЯ_СТРОКА/" .env && docker compose up -d'
```

И добавить в интеграцию формы параметр `key` с этим значением. Проверка глазами:
отправь `simulate_yandex.py` без `--key` — должен прийти `rejected`; с `--key` — `accepted`.

Ключ в журнале не оседает: при записи он заменяется на `***`.

---

## Чего не делать

- Не вставлять в тело «Ответы на вопросы в виде JSON» — формат внутренний и может
  измениться, а нам нужны конкретные ключи.
- Не добавлять в форму поле «роль» — она задаётся константой в интеграции.
- Не отправлять по одной форме обе роли: приёмник различит их только по `s_role`.
