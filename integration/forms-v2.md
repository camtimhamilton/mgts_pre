# Приём новых анкет ПУЛЬС v2

Приёмник реализован. Подключение реальной формы требует доступа владельца формы и опубликованного адреса сервера. Локальный JSON-RPC тест проверяет адаптер и повторную доставку. Статус подключения реальной формы нужно проверять отдельно.

Яндекс Формы позволяют настроить JSON-RPC POST с именованными параметрами либо запрос заданным методом с собственным JSON-телом. Это конфигурируемое действие формы. Формат ниже задаётся в её настройках. Официальная инструкция также требует IPv6 и разрешения сети Форм в файрволе. [Документация Яндекс Форм](https://yandex.ru/support/forms/ru/send-request)

## Настройка

1. Запустите dashboard с `DB_PATH=data/pair-v2.db` и ML-сервис по инструкции совместного запуска.
2. Установите `INGEST_KEY` в окружении dashboard. Добавьте этот секрет в заголовок `X-Ingest-Key` HTTP-действия формы. Доступ к UI и исходным ответам ограничьте локальной машиной либо существующим корпоративным шлюзом доступа.
3. В форме откройте «Интеграции», добавьте «Запрос JSON-RPC POST», укажите `https://<ваш-сервер>/api/v2/forms/yandex`, метод `submit`.
4. Добавьте именованные параметры из таблицы. Используйте переменные ответов через интерфейс Форм. Для текстов используйте именованные параметры JSON-RPC, чтобы переводы строк и кавычки сериализовал сервис Форм.
5. Отправьте тестовую анкету. Проверьте ответ интеграции, `/api/v2/source/{source_id}` и изменение `/api/v2/revision`. Затем убедитесь в обновлении матрицы.

| Параметр | Значение |
|---|---|
| `form_id` | Устойчивый идентификатор формы, задаётся в настройках |
| `response_id` | Переменная ID ответа формы, обязательна |
| `revision_id` | Идентификатор редакции ответа или timestamp редакции, если доступен |
| `role` | Константа `mentor` либо `intern` |
| `intern_id` | Ответ на вопрос ID стажёра |
| `mentor_id` | Ответ ID наставника в анкете наставника |
| `department` | Ответ на вопрос подразделения |
| `month` | Контрольная точка целым числом 1–6 |

Оценки наставника передаются плоскими параметрами `clarity`, `quality`, `autonomy`, `deadlines`, `initiative`, `team`. Тексты передаются параметрами `comment`, `attention`.

Оценки стажёра передаются параметрами `clarity`, `support`, `workload`, `interest`, `growth`, `team`, `satisfaction`. Тексты передаются параметрами `difficulties`, `barriers`.

Названия соответствуют исходным вопросам XLSX. Шкала сохраняется 1–5. В альтернативном HTTP JSON-действии можно передать словари `ratings` и `texts` с этими ключами. Полный перечень исходных заголовков хранится в `app/pair_import.py`.

Наставник связывает свой ID со стажёром явно. Первую анкету стажёра можно принять после импорта истории, приёма анкеты наставника либо явного `POST /api/v2/pairs` с подтверждёнными `mentor_id`, `intern_id`, `department`. Неизвестная пара отклоняется. Конфликт наставника или подразделения требует проверки реестра владельцем.

Повторное событие сохраняет исходный `source_id`. Новая редакция сохраняется новой версией анкеты. При наличии `revision_id` его повтор с другим содержимым отклоняется. Когда редакция отсутствует, используется хеш содержимого. Для различения возврата к старому содержимому и задержанной повторной доставки необходим устойчивый идентификатор редакции от источника. Новый ответ формы должен иметь новый `response_id`.

## Локальное событие для проверки

Пример содержит синтетические данные. Передача его на локальный сервер проверяет настроенный формат действия Форм.

```json
{
  "jsonrpc": "2.0",
  "method": "submit",
  "id": 1,
  "params": {
    "form_id": "synthetic-mentor",
    "response_id": "synthetic-answer-1",
    "revision_id": "1",
    "role": "mentor",
    "intern_id": "synthetic-intern-001",
    "mentor_id": "synthetic-mentor-001",
    "department": "Синтетический пример",
    "month": "1",
    "clarity": "2",
    "quality": "4",
    "autonomy": "3",
    "deadlines": "4",
    "initiative": "4",
    "team": "4",
    "comment": "Нужно уточнить ожидаемый результат задачи.",
    "attention": "Проверить понимание задачи на встрече."
  }
}
```

Сохраните событие в UTF-8 `data/yandex-v2-test.json` и выполните в PowerShell.

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/v2/forms/yandex `
  -ContentType 'application/json; charset=utf-8' `
  -Headers @{'X-Ingest-Key'=$env:INGEST_KEY} -InFile data/yandex-v2-test.json
```

Первый ответ содержит `result.status=accepted`, повтор содержит `duplicate`. Измените `revision_id` и оценку, чтобы получить новую версию. Историческая версия остаётся доступной по прежнему `source_id`. JSON-RPC ошибки возвращаются HTTP 200 с `error.code=-32602`, без конфиденциального содержимого в сообщении. Неверный секрет возвращает HTTP 401.

Новая версия инвалидирует кеш аналитики и сохранённые сценарии. Фоновый пересчёт вызывает ML-сервис, после чего публикуется событие обновления. При ошибке ML интерфейс получает статус недоступности. Метаданные и исходные ответы хранятся в SQLite отдельно от технических логов. Рекомендуемый запуск прототипа привязывает оба сервиса к `127.0.0.1`.

Проверка адаптера выполняется командой `python -m pytest tests/test_pair_persistence.py -q`. Она включает JSON-RPC повтор, редакцию, конфликт редакции, идемпотентный XLSX импорт, восстановление сценария и инвалидирование после новой анкеты.
